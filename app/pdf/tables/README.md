# 统一表格结构与兼容适配

当前已接入统一模型、原生/Docling 后端及逻辑表组装。后端说明见 [backends.md](backends.md)，第 6 项的关联、续接和切片规则见 [logical.md](logical.md)。

第 7 项已补齐行组/列组切片与检索后的原始支持证据，见 [retrieval.md](retrieval.md)。完整进度见 [修改队列](queue.md)。

第 8 项已接入表格级使用状态、结构/来源/续表检查和分色单元格复核，见 [quality.md](quality.md)。当前切片 v13、质量规则 v6；真实模型和业务样本验收仍有明确边界。

模型定义见 `app/schemas/table.py`：

- `TableCell` 保存页内行列、可选跨行跨列、原始文字、来源位置、文字来源、行列表头和单位单元格引用。规范化数值使用十进制字符串，原文不作覆盖。
- `TableFragment` 保存单页物理区域、维度、单元格、可选表头行、后端及原始输出。
- `LogicalTable` 引用片段和原单元格，保存表头路径、逻辑数据行、重复表头、单位、脚注及候选续接关系；不复制单元格原始值。

`ParsedPdf` 新增 `table_schema_version`、`table_fragments`、`logical_tables`。已有 Repository 的 `asdict` 序列化自动持久化这些字段，无需改动 SQLite 表结构。

## 状态约定

| 单元格状态 | 意义 |
| --- | --- |
| text | 已识别的非空文字，包括字符串 `"0"` |
| blank | 确认空白，不是零值 |
| unreadable | 单元格存在，但文字识别失败 |
| covered | 已确认的合并占位，必须指向同一片段中的非占位锚点 |
| unknown | 证据不足，无法确定内容状态 |

未知跨度为 `None`；不把它自动视作已确认的 `1`。未知表头行也为 `None`，区别于已确认没有表头的空列表。

表格的 `structure_status` 和 `provenance_status` 默认为 `unverified`。它们描述表格结构及来源的验证程度，与自动质量报告的 `passed/review/blocked` 分开。

构造模型时校验索引、跨度、状态、重复 ID、片段归属、边界和占位锚点。单元格覆盖冲突、表头关系、来源坐标有效性以及跨页组装的一致性仍由后续质量规则负责。

## 当前解析链路

新解析通过后端直接创建统一片段；原生框线几何可恢复合并跨度，无框线候选使用文字对齐策略。Docling 可选且默认不启用。`legacy.py` 仅为历史 `basic_grid` 数据提供兼容视图。

历史适配器不猜测合并跨度、多级表头和跨页关系。旧数据中的 `None` 格保留为 `unknown`。新解析在页内处理结束后建立逻辑表及表头引用；未知表头保留为 `None`，不删除首行。

当前解析器为 `native-v15:logical-tables-v1`，处理指纹包含解析、切片、后端版本及配置；重新上传时使用新链路，旧资产不会自动重建或清空。

## 资产恢复

`restore_pdf()` 支持缺少表格字段的历史 JSON，在内存中构造兼容片段。原始资产、元素 payload 和历史解析器版本不变。恢复对象使用当前表格 schema v1，后续序列化采用该版本。

明确保存为空的 `table_fragments` 不从旧 payload 重建。未知的未来 schema 被明确拒绝，不静默降级。JSON 中各层表格来源恢复为 `SourceSpan`，规范化 bbox 恢复为 tuple；不透明的引擎原始输出遵循标准 JSON 的数组表示。

逻辑表的标题、单位和脚注具有独立来源；组装只引用原单元格，不覆盖原始文字、坐标或后端输出。新增加的字段具有默认值，旧 schema v1 资产仍可恢复。

后端整理后的配置、导入服务和紧凑存储说明见 [后端处理链路](../../indexing/README.md)。新表格证据 schema v2 从解析片段读取原始单元格，仍兼容旧 schema v1 内嵌证据。
